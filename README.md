# 一剑一蓑烟雨录

像素风文字武侠 RPG。浏览器版负责规则原型，Unity 负责后续场景与表现迁移。

## 当前结构

```text
根目录
├── data/                     游戏规则、数值与地图数据
│   ├── world.json            天下地图、州府与城际交通线
│   ├── maps.json             江湖点与旧地图数据
│   └── city_content.json     州府级 explore 内容
├── assets/                   场景与美术素材
├── docs/                     项目规范与全局 ID
├── unity/QinghePrototype/    Unity 清河最小原型
└── 浏览器版 HTML / JS         当前规则原型机
```

## 天下地图结构

地图采用两层，不把所有地点摊在一张扁平网格：

```text
天下大地图（州府级）
├── 中原：开封、洛阳、应天
├── 运河/江东：扬州、建康、杭州、苏州、鄂州
├── 海路：明州 → 泉州 → 广州
└── 荆湖/西南：鄂州 → 长沙 → 成都

州府
└── 江湖点（清河、山门、秘境等）
```

州府负责长途旅行、区域关系和城市级 explore；江湖点继续使用原有短途玩法。历史城市不替换现有清河、竹径、山门等节点。

## 地图阶段

### 第 1 步：中原与基础四城

开封、洛阳、扬州、杭州作为天下地图骨架。清河等旧江湖节点挂在对应州府下。

### 第 2 步：运河 / 长江线

增加苏州、建康、鄂州、应天，并形成：

```text
开封 → 应天 → 扬州 → 建康 → 杭州 → 苏州
                    ↓
                   鄂州
```

近城通常 2～3 程，跨区域 4～5 程，不做全互连。

### 第 3 步：海路 + 荆湖/西南

增加明州、泉州、广州、长沙、成都：

```text
杭州 → 明州 → 泉州 → 广州

鄂州 → 长沙 → 成都
```

海路使用较高 cost 制造远行感；杭州不直达泉州。长沙、成都保持少边、高 cost，体现远端位置。

暂不做城内多层街区，也不为每座城市建立完整江湖网。

## 州府级玩法

每座已开放州府至少拥有：

- `tier: city`
- 区域、特色标签和大雍话本文案
- 2～3 条城市 explore
- 银两、见闻、经验或轻伤等轻量反馈
- 有现成江湖点才设置 `children`，没有就保持空列表

城市内容位于 `data/city_content.json`，避免把地图拓扑和玩法文案混在一起。

## 存档兼容

旧存档的 `location` ID 不变。州府归属通过 `data/maps.json` 的 `parent` / `region` 信息推导。新增城市只增加 ID，不要求旧存档迁移。

## 双端职责

```text
浏览器 = 规则原型：数值、玩法、存档、剧情规则
Unity   = 表现层：场景、镜头、角色、交互、动画
共享    = location / npc / skill / rank 等稳定 ID
```

不要在 Unity 和浏览器各维护一套互相冲突的数值。全局 ID 以 `docs/id_map.json` 为参考。

## Unity 清河原型

位置：`unity/QinghePrototype/`

当前验证清河五个交互点：客栈·市井、老周、医馆、拳场·学艺、官道·出城。原型目标是验证“场景 → 交互 → 规则入口”的链路，而不是提前制作完整场景。
